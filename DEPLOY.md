# Deploying ReceiptTrust to Render

Deploy three resources:

| Resource            | Type              | What it is                                  |
|---------------------|-------------------|---------------------------------------------|
| `receipttrust-db`   | PostgreSQL 16     | Managed database                            |
| `receipttrust-api`  | Docker web service| Spring Boot API (from `Dockerfile`)         |
| `receipttrust-web`  | Static site       | React frontend (from `frontend/`)           |

> **Free tier:** Render Blueprints (`render.yaml`) now require a paid workspace, so on a
> free account use the **manual** steps below. The `render.yaml` in this repo is kept only
> for reference / paid workspaces.

## Prerequisites

- The repo pushed to GitHub (or GitLab/Bitbucket).
- A free [Render](https://render.com) account.

---

## Manual deploy (free tier)

Create the three resources by hand in the Render dashboard, in this order.

### 1. PostgreSQL
- **New +** → **PostgreSQL**. Name `receipttrust-db`, database `receipttrust`,
  user `receipttrust`, **Free** plan. Pick a region and remember it.
- Open the DB → **Connections** and copy the host, port, database, username, password.
- Free Postgres is deleted after 30 days and is limited to one instance.

### 2. Backend API (Docker web service)
- **New +** → **Web Service** → connect the repo → **Runtime: Docker** (uses the `Dockerfile`).
- Same **region** as the DB. **Free** plan. **Health Check Path**: `/actuator/health`.
- Environment variables:

| Key | Value |
|-----|-------|
| `SERVER_PORT` | `8080` |
| `DB_URL` | `jdbc:postgresql://<HOST>:<PORT>/<DB>` (built from the DB's connection info) |
| `DB_USERNAME` | the DB user |
| `DB_PASSWORD` | the DB password |
| `JWT_SECRET` | a Base64 32-byte+ secret (generate one; keep it stable) |
| `FRONTEND_ORIGINS` | set after step 3 to the static site's https URL |

Generate a JWT secret (PowerShell):
```powershell
$b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
```

Note: free web services have **no persistent disk**, so leave `RECEIPT_DIR`/`PROFILE_DIR`
unset (they default to a container-local path). Uploaded images are lost on restart —
acceptable for a free-tier demo. Debts, items, and receipt metadata live in Postgres and persist.

### 3. Frontend (static site)
- **New +** → **Static Site** → same repo.
- **Build Command**: `cd frontend && npm ci && npm run build`
- **Publish Directory**: `frontend/dist`
- Environment variable: `VITE_API_BASE_URL` = the API service URL (e.g. `https://receipttrust-api.onrender.com`).
- **Redirects/Rewrites**: add Source `/*` → Destination `/index.html`, Action **Rewrite** (SPA routing + PWA).

### 4. Wire cross-URLs and redeploy
- On the **API**: set `FRONTEND_ORIGINS` = the static site URL, then redeploy.
- On the **web**: confirm `VITE_API_BASE_URL` = the API URL, then **Manual Deploy → Deploy latest commit**
  (the frontend must rebuild so the API URL is baked into the bundle).

### Free-tier notes
- Web services **sleep** after ~15 min idle; first request after that cold-starts in ~30–60s.
- The installable PWA works (Render serves HTTPS). For the installed app to reach the API,
  `VITE_API_BASE_URL` must be set at build time (step 3).

## Blueprint (render.yaml) — paid workspaces only

> Not available on the free tier. Use the manual steps above unless you have a paid
> Render workspace.

## Step 1 — Create the Blueprint

1. In Render, click **New +** → **Blueprint**.
2. Connect the repository. Render detects `render.yaml` and lists the DB, API, and static site.
3. Click **Apply**. Render provisions the database first, then builds the API image and the
   frontend.

The database credentials are generated by Render. The API automatically receives them through
the `fromDatabase` mappings in `render.yaml` (host, port, name, user, password), and assembles
the JDBC URL. **You never hardcode DB credentials.** To view them: open the `receipttrust-db`
resource → **Info** tab → *Connections* (internal and external connection strings, username,
password).

## Step 2 — Wire the two cross-origin URLs

`render.yaml` marks these as `sync: false` because each needs the other service's public URL
(with the `https://` scheme), which only exists after the first deploy.

1. Once both services are live, copy their URLs from the Render dashboard, e.g.
   - API:  `https://receipttrust-api.onrender.com`
   - Web:  `https://receipttrust-web.onrender.com`
2. On **receipttrust-api** → **Environment**, set:
   - `FRONTEND_ORIGINS = https://receipttrust-web.onrender.com`
3. On **receipttrust-web** → **Environment**, set:
   - `VITE_API_BASE_URL = https://receipttrust-api.onrender.com`
4. **Redeploy both** (Manual Deploy → Deploy latest commit). The frontend must rebuild so the
   API URL is baked into the static bundle; the API restarts to pick up the CORS origin.

## Step 3 — Verify

- API health: open `https://receipttrust-api.onrender.com/actuator/health` → `{"status":"UP"}`.
- Flyway runs automatically on boot and creates the schema (`V1__init.sql`). Check the API
  service logs for `Successfully applied 1 migration`.
- Open the frontend URL, register an account, and use the app.

## Environment variables reference (API)

| Variable            | Source / value                                    |
|---------------------|---------------------------------------------------|
| `DB_URL`            | `jdbc:postgresql://${DB_HOST}:${DB_PORT}/${DB_NAME}` |
| `DB_USERNAME`       | from `receipttrust-db` (`user`)                   |
| `DB_PASSWORD`       | from `receipttrust-db` (`password`)               |
| `JWT_SECRET`        | generated by Render (kept stable across deploys)  |
| `FRONTEND_ORIGINS`  | the static site URL (set in Step 2)               |
| `RECEIPT_DIR`       | `/data/storage/receipts` (on the persistent disk) |
| `PROFILE_DIR`       | `/data/storage/profiles` (on the persistent disk) |
| `SERVER_PORT`       | `8080`                                            |

## Notes and caveats

- **Free plan sleeps.** Free web services spin down after inactivity; the first request after
  idle takes ~30–60s. The free Postgres plan also expires after a set period — upgrade for
  anything long-lived.
- **Persistent disk.** Uploaded images are stored on a 1 GB disk mounted at `/data/storage`.
  Attaching a disk prevents free-tier horizontal scaling (fine for this MVP).
- **Receipt image `<img>` tags.** `GET /receipts/{id}/image` requires a JWT via the
  `Authorization` header. Plain `<img src>` requests can't send that header, so images render
  only where the browser can attach credentials. For production, consider signed URLs or
  serving via an authenticated fetch + blob URL. Out of scope for this MVP.
- **Region.** The blueprint uses `oregon`. Change `region:` in `render.yaml` if you prefer
  another; keep the DB and services in the same region for low-latency internal networking.

## Local Docker (for parity testing)

The same image runs locally against the Docker Postgres from `docker-compose.yml`:

```powershell
docker compose up -d                      # starts postgres on host port 5433
docker build -t receipttrust-api:local .
docker run --name rt-api --network receipttrust_default -p 8090:8080 `
  -e DB_URL="jdbc:postgresql://receipttrust-db:5432/receipttrust" `
  -e DB_USERNAME=receipttrust -e DB_PASSWORD=receipttrust `
  -e JWT_SECRET="<base64-32-byte-secret>" receipttrust-api:local
# health: http://localhost:8090/actuator/health
```
